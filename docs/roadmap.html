Roadmap

The roadmap is not a research wish list. It is a five-year build-and-commission plan that begins only after the nonprofit crosses its funding threshold. The purpose of each phase is to eliminate one class of execution risk before the next scale step.

The schedule starts after funding lock

The five-year clock should not start while the organization is still begging for survival money. It starts when capital, authority, and the core team are in place.

Technology baseline

The baseline detector concept is a 1 bar xenon gas TPC. The roadmap is therefore organized around the hard questions for that choice: energy resolution at scale, long-drift stability, gas purity, diffusion, readout area, ML-assisted topology, radiopurity, xenon handling, and underground installation.

The baseline can be challenged

The technology paper and early demonstrations must earn the baseline. If a core assumption fails under integrated test, the program should know quickly and change direction deliberately.

Phase 0: Capital lock and command structure

ZeroNu first establishes the nonprofit, decision authority, budget threshold, reporting cadence, and legal structure. The current threshold is US$200 million. The founder moves full time only after committed funding is sufficient to make the program real.

Deliverables:

  • nonprofit structure and decision rights;
  • US$200 million capital threshold, pledge terms, and spending rules;
  • policy for directing industrial-invention proceeds into the mission;
  • project-partner buy-in standard separating partners from paid staff;
  • focus charter that rejects secondary requirements unless they strengthen the 0νββ measurement;
  • public-funding acceptance rule: no scope inflation, no committee veto over the core mission;
  • five-year staffing plan for the core team;
  • public milestone map and technical review cadence.
Capital is an engineering input

Funding determines staffing, procurement, schedule realism, QA depth, vendor leverage, and test infrastructure. Treating capital as external to engineering is one reason large experiments drift.

Industrial revenue before the threshold

Before the full detector program launches, ZeroNu can generate mission capital by inventing instruments, sensors, detectors, and software for industrial customers. That revenue stream should be measured by how much non-dilutive force it adds to the final experiment.

A sharp machine

The detector should be designed like a sharp instrument for one decisive question. Other physics is acceptable only when it does not change the machine, schedule, or decision structure.

Partner standard

Partners must carry personal downside and commit upside to the mission. Paid staff are different: the experiment should hire excellent workers without demanding personal financial sacrifice.

Phase 1: Integrated module

The first technical milestone is not a beautiful isolated subsystem. It is an atmospheric-pressure xenon TPC module that forces the real interfaces to appear: vessel materials, drift, gas purity, readout, calibration, background control, reconstruction, and stability.

Deliverables:

  • integrated 1 bar xenon module with energy response, track topology, background control, and uptime measured together;
  • drift, diffusion, attachment, and gas-purity measurements under realistic operation;
  • first topology dataset for signal-like and background-like event classes;
  • low-background material handling and contamination controls;
  • calibration path that can scale;
  • QA procedure that catches defects early enough to matter.
Kill paper progress

A technique demonstrated alone is not yet a detector. A milestone counts only when it survives contact with the rest of the system.

Phase 2: Multi-module system test

The second milestone tests whether the TPC behaves like a system instead of a stack of prototypes. Gas handling, purification, calibration, readout, data acquisition, analysis, monitoring, maintenance, and failure recovery must all run together.

Deliverables:

  • multi-module operation with realistic services and controls;
  • scalable gas circulation, purification, and recovery procedure;
  • stress-tested calibration and monitoring;
  • data pipeline from detector state to analysis products;
  • validated ML topology pipeline with control samples and bias checks;
  • measured uptime and recovery procedure;
  • procurement and assembly model for the next scale.
Feedback loops decide speed

The program must be able to discover a fault, reproduce it, assign ownership, fix it, and verify the fix quickly. If debugging takes months, the model has failed.

Phase 3: Pilot-scale deployment

The pilot is the rehearsal for the full build. It uses production materials, production QA, realistic gas systems, realistic assembly procedures, and real operations constraints. Its job is to prove that the detector can be manufactured and maintained, not merely imagined.

Deliverables:

  • production-like procurement and assay flow;
  • assembly yield and rework statistics;
  • validated background model from real operating data;
  • topology-discrimination performance under real detector conditions;
  • readout cost and channel-count model for full scale;
  • underground hall, shielding, and service-integration plan;
  • frozen design for full-scale procurement;
  • operations plan for lean long-duration running.
The pilot must be uncomfortable

A pilot that avoids logistics, contamination risk, maintenance burden, and data-quality problems is theater. The pilot must expose exactly the problems that would otherwise appear during the full build.

Phase 4: Full-scale build and commissioning

The full-scale atmospheric-pressure TPC is constructed only after the integration path is proven. This phase is xenon procurement and recovery planning, vessel construction, underground logistics, installation, commissioning, calibration, stability, and first physics-quality running.

Deliverables:

  • full detector installation and commissioning;
  • xenon inventory, purification, and recovery controls;
  • stable data-taking mode;
  • documented detector state and calibration;
  • first public technical report;
  • open-data release after stability criteria are met.
Open data is part of the bargain

Once the detector is stable and calibrated, the data belongs to the scientific question. Releasing it without embargo maximizes analysis power and prevents the experiment from becoming private intellectual property.

Phase 5: Lean operation for the world

After commissioning, the program transitions from build mode to operating mode. The core team can shrink. A small technical staff maintains the detector, monitors stability, releases data, and supports external analysis.

Deliverables:

  • maintenance plan and spare strategy;
  • public data documentation;
  • regular detector-status reports;
  • external analysis access and reproducibility package.

The endpoint is not a monument. It is an answer.
